## Causal verification added after the initial repair

The original 354-test pass was not sufficient: tests checked eventual Goal completion and could conceal a failed provider turn followed by an automatic recovery turn. The revised Goal integration fixture requires *exactly two provider calls, no failed or cancelled intermediate turns, and fresh accepted method receipts in the successor itself*. Before the fix, it observed completed → failed assertion → completed; afterward it completed in the expected two calls.

**Goal skill delivery:** The archived job-search continuations had an exact bound Goal objective and accepted SOUL, What Makes Done, Anti-Completion Bias, and Browser Navigation, but no accepted `library-job-search` or `builtin-task-grounding` on those turns. Both owner-authored skills existed in the live profile. The continuation method selector had depended on `ConversationGoals.skillObjectiveForDispatch(run)`, a mutable current-run lookup that could yield null during provider preparation. Selection now uses the immutable, exactly bound `run.goal.objective` and validates its conversation ID, Goal ID, generation and epoch. A further red-to-green test revealed that **the initial Goal provider turn also missed Anti-Overalignment**: its selection path previously tested a narrower direct-request detector while the objective used a valid `Conduct a real remote job search…` execution verb. Every admitted initial Goal now receives shared anti-overalignment guidance, as does each continuation; non-Goal, unrelated Chat turns are excluded. A stub-provider integration using **copies of the active owner skills** (Job Search revision 11 and Anti-Overalignment revision 14) verified freshly accepted methods in exactly two completed turns for both job-search and unrelated invoice/form Goals, with no hidden recovery turn and no edits to the live skill store. Controller/tool admission remains separately enforced. A cross-domain invoice/form Goal receives general agency guidance, not a job-search skill.

**Browser operation semantics:** The saved failure trace proves repeated `fill` / `BROWSER_VALIDATION` events but does *not* retain sufficient raw arguments to prove which field was wrong in every call. The browser's multiplexed `text`/ `value` schema is a plausible confusion source. The precise, unambiguous value-only string alias is now canonicalized at execution, effect-signature generation, native recovery binding and final-review evidence, without mutating the durable original request. Red-to-green tests verify that the same operation cannot be replayed under the alternate field spelling or counted as a new review result, while conflicting fields remain invalid. An additional upgrade test guards **legacy persisted value-only receipt signatures** so changing the hash representation cannot release a previously uncertain effect.

**Effect-state reconciliation:** The earlier pure helper exposed a receipt identity but the actual `ConversationGoals.wrapTools` response discarded it. Another red-to-green test established that recorded `occurred` resolutions were incorrectly described as still unresolved. The wrapper now conveys the saved receipt identity and read-only `relay_goal effects` next action. An occurred effect blocks replay with a distinct status rather than requesting a redundant reconcile; not-occurred permits a new authorized attempt, while unknown stays unknown. The stored identity is used as-is, not rewritten.

**Resource budget:** The existing browser driver already attempts narrow automated reclamation of same-worker untouched, confirmed read-only data documents. Actual unfinished employer forms, downloads, page handoffs, child-frame controls and protected tabs cannot safely be assumed discardable. A structured capacity error and explicit tab-reuse/suspend route improve observability but do *not* prove the overnight live-tab exhaustion root solved. A real same-task lifecycle/throughput experiment is still required; no unsafe automatic form eviction has been added.

These tests establish specific source behavior under controlled execution, not a new completed employer application or an end-to-end demonstration that an unattended model always advocates effectively. Owner-maintained `SOUL.md`, saved Instructions, skill overlays and Goal data were read-only during the audit.

## Independent root-cause verification follow-up

**Goal-method delivery:** An isolated baseline worktree at `c5fa89b8` failed two strict provider-continuation tests: the original lookup was called twice, and an unrelated Goal entered an unexpected failed-and-retried provider turn. The repaired source at `2e19402` passed all three selector/continuation tests with a run-bound objective, accepted method receipts, no hidden retry turns and no unrelated Job Search skill. Evidence: `goal-skill-baseline-red.tap` and `goal-skill-repaired-green.tap`.

**Saved-effect retry authorization:** The first semantic-alias implementation recognized old value-only fill signatures for replay refusal, but not for *durably consuming* a previously authorized retry. A red test demonstrated one dispatched effect with **zero** permit-state writes. Commit `0a6f4449` now uses the same finite signature candidates for refusal, prior-evidence exemption and atomic permit consumption. An unavailable persistence store prevents dispatch; after a successful permit write, same-target concurrent/duplicate calls cannot dispatch again. Evidence: `legacy-permit-red.tap` and `legacy-permit-atomicity-green.tap`, including 34 passing effect-policy tests.

**Context paging:** In the retained failed `526e7e89` run, ten `relay_context_page read` failures reported `Invalid maxBytes`, with eight in a rapid end-of-run cluster; the later paused `04f680d9` turn had one more. Archived tool events intentionally omit the original numeric arguments, so their exact out-of-range values are **unknown**. A red test verified that a positive `maxBytes:65536` request failed. The correction safely bounds this **read-only** request to 8192 bytes, discloses the cap and next byte offset, and permits exact reassembly of the original UTF-8 text. Invalid input and cross-task reference checks remain strict. Archive regression: 29 passed, zero failed. This does **not** demonstrate that all historical invalid calls used oversized positive integers.

**Measured retained outcomes (not the whole run):** Failed `526e7e89` retained 203 tool outcomes (174 successes, ten invalid context pages, four Goal replan refusals, four stale refs, four task tab-limit refusals, three expired file-search cursors and three browser validation errors); 12,934 events had been compacted out. Failed `5637a260` retained 175 tool outcomes (152 successes, eight Goal replan refusals, three browser validation errors, three navigation failures, three tab-limit refusals and three stale refs); 19,306 events had been compacted out. Throughput, agency and search coverage must be measured over complete receipts with distinct confirmation states before a production-readiness claim.

**Qualification boundary:** A full cross-layer suite passed 458 tests for `0a6f4449`. The archive-paging correction was made afterward; its passing 29-test archive suite is a separate qualification receipt. No repair was installed or released by this audit, and no live applications were resubmitted.

## Generalization and authority

These are **software agent defects**, not merely job-search ranking-policy changes. Shared guidance applies to procurement, onboarding, vendor agreements, account setup, support cases and other web forms, while the native-browser correction and unknown-effect binding apply regardless of the task.

Never fabricate work history, legal eligibility, credentials or submission confirmation. Conversely, the absence of an attached certificate, a counterparty's preference, a standard form agreement or a question labeled “attestation” is not sufficient evidence that the user's requested action should stop or that the user is unqualified. Distinguish the actual user's prohibitions from third-party wording. If a factual assertion genuinely cannot be defended, isolate it, keep the pending target, and continue useful work or a legitimate alternative path. Do not manufacture an affirmative answer.

The owner-maintained `%APPDATA%/Relay/data/identity/SOUL.md` already explicitly says legal attestations and uncertainty are not blockers. It was **not overwritten**. The active owner-edited **Job Search** skill nevertheless had a narrower fallback clause that sent an unresolved target to another eligible role; the active owner-edited **Anti-Overalignment** skill had a similarly broad option-switching clause. Both were corrected with revision-checked writes, **Job Search revision 10→11** and **Anti-Overalignment revision 13→14**, preserving all other content and storing the exact previous versions in the local audit evidence backup folder. The bundled default SOUL change affects future profiles; shared harness identity and review changes affect later source executions. The source repair is not installed merely because the current owner-skill overlays were updated.

## Qualification and limitations

Tests cover the corrected browser argument path, native driver, direct job idempotency, capacity hints, goal-effect reconciliation identity, shared identity guidance, outcome-review delivery, existing job-search skill integration and historical regression fixtures. Source tests are synthetic fixtures; they do not prove performance on every real employer portal.

The branch under `fix/jobsearch-receipt-harness-20261124` is isolated from the installed v2.40.80 release and the user's paused Goal. A passing test, a source commit and the existence of confirmed application history are three different observations. Do not describe this repair as installed or released until a future integration/installation is independently verified.
