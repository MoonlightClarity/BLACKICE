An adopted analytical Plan, a maintained outline, favorable intent, absence of question keywords, and HTTP receipt integrity do not establish completed work. The model's failed execution remains a failure after the host repairs.

## Seven-case semantic review

The following findings refer to the original final drafts, not to completed external actions. The [semantic review record](../verification/agency-20261104/semantic-review.json) preserves the distinctions and short output excerpts.

That deficit was not needed to answer the actual question. Truthfulness alone does not make every negative fact relevant to a counterparty-facing answer. |
| Explicit production-SQL question | Accepted | **Sound on this fixture.** The answer gave a direct, truthful “No,” described supported experience, and chose to proceed because no minimum threshold was stated. The negative fact was material because it was directly requested. |

Its instruction that the user perform the backup added needless handoff wording, but this no-tools experiment does not demonstrate an actual refusal of authorized live work. |
| Useful clarification | Rejected: `USER_AGENCY_COMPARISON_REQUIRED` | **Useful clarification with an unsupported reassurance.** The model asked which dock the event uses, supplied the independent packing checklist, and computed costs of proceed 40, ask 2, defer 10. “Either entrance works” was not supported by the record. No actual retry was tested. |

These results neither support a blanket pass nor a numerical reliability claim. The SQL and role failures show why audience relevance and practical judgment need review beyond schema acceptance. The backup and clarification drafts show that sound arithmetic or a sensible action can coexist with an invalid checkpoint.

## Repairs established by the diagnostic work

The compatible Chat Completions adapter now projects a detached wire copy of the output schema to omit unsupported `uniqueItems`. It retains the original schema for host acceptance. If uniqueness lies beneath an exclusive `oneOf` branch, where removal can change matching behavior, it selects the explicit `schema_uniqueness_projection_unsafe` prompt-and-host-validation fallback. Native and Responses schema paths retain their existing contracts.

The verified uniqueness invariant is specifically the **string IDs in raw user-cost `hardConstraints[].blockedOptionIds`**. The unchanged host evaluator rejects duplicate IDs on this path. This is not a claim that BLACKICE now provides generic JSON Schema uniqueness validation for arbitrary object arrays.

The sequential planning guard rejects malformed edit-operation collections before examining reconciliation or revisits, using structured `INVALID_PLAN_EDIT` results. It does not coerce JSON strings or weaken plan, ledger, or dispatch checks. The missing-plan recovery message now states the complete current leaf and operation shape. Focused regressions and the observed r4 structured rejections support these narrow repairs. See [regression evidence](../verification/agency-20261104/regression-summary.json) and the [schema compatibility note](provider-structured-output-20261030.md).
