# Action-oriented Directory experiment

Status: isolated implementation, not enabled in the installed app or included in the production recovery candidate. This isolated branch starts from d4639eb and must incorporate verified release corrections before live comparison. Constructor/host options actionDirectory=true selects it; false preserves current phase Directory. An experimental build can be launched with BLACKICE_DIRECTORY_ACTIONS=1 on a disposable test profile, so ordinary Directory-enabled BLACKICE tasks exercise the same host dispatcher; Directory off remains off. No environment or profile setting has been changed in the running app. This is a structural experiment with a separate typed-overflow containment path. Neither has live-model validation yet.

## Why structure changes

One whole-night work phase with 118 incomplete checkpoints failed to provide a bounded, recoverable account of ongoing actions. Receipt novelty is not outcome progress. Eleven compactions and an earlier peak do not prove the terminal cause: final nonzero input was 451510. Existing phase files remain evidence, not a migration target to erase.

## Boundaries and authority

A host attempt is one admitted tool invocation, durably recorded before dispatch. Its outcome links the exact existing receipt file and digest; a successful tool call is not independent confirmation of the user's outcome. A meaningful action is a model-authored objective with inputs/state, decision, next action and explicit evidence links. It may span many attempts or inspections. Action revisions form parent-linked records, not a global mutable summary. Model notes are always agent-authored; current host-supplied instructions and source input have separate phase-authority records. Corrections reference originals and never delete them. Model notes cannot clear Goal effect fences or confer authorization.

Action boundaries are explicit and revisable. Different exports or edits with equal arguments remain distinct attempts. Only an identical host invocation ID is prevented from being admitted twice; semantic equality never deduplicates legitimate work. An attempt lacking an outcome remains unknown after failure/restart, not presumed unsent. Failed observation and uncertain external effect remain distinct in the original receipt and Goal policy.

## Concurrency and storage

Immutable event IDs derive from event identity, with a separate content hash. Same-process writes serialize; exclusive permanent identity claims prevent two processes from replacing an event. Synced pending JSON is renamed into view only when complete. A crash leaves an inspectable unpublished reservation, not an absent attempt; independent work remains available. Conflicting content for the same identity fails. Concurrent revisions with the same parent are retained as forks, requiring an explicit agent-authored reconciliation relation rather than last-writer-wins. Corrupt published records still fail validation and are retained. Files are synced before returning, but filesystem power-loss behavior and parent-directory durability remain unverified.

The default working index includes current action revisions, unlinked outcomes, unknown effects, pending attempts and authority/context sources. Older revisions remain accessible by exact ID or view:events; actionId selects an action's full revision history. This changes the organization of the working state, not only its token threshold. Pagination carries a revision and rejects continuation after concurrent updates; exact IDs remain stable. Phase inputs and authority snapshots use immutable per-phase names in the experiment, preventing later phases from invalidating earlier references. Existing tool-result files hold full outcomes, avoiding another full transcript copy in the journal. source:true retrieves and hash-verifies the original receipt. No deletion, compaction of originals or rewrite of historic data occurs. The journal lives at conversation scope so successor runs can inspect prior action records. Existing prior-context imports now receive exact attributed source links; no legacy claim becomes verified merely because it was imported. Comprehensive legacy-history reconciliation still needs live-model validation.

## Incremental state and recovery

Attempts and outcomes persist within work, without waiting for phase completion. relay_directory_action records action revisions incrementally. It does not execute work. After typed CONTEXT_OVERFLOW, the experimental runner waits for runtime settlement, refreshes authority, saves a recovery packet and starts a fresh provider session with a unique tool-call namespace. It points to exact journal sources and the latest checkpoint instead of replaying the transcript. Cancellation is checked before admission. Two rollover attempts maximum and repeated exhaustion without new outcome records terminate explicitly. That limit is containment, not proof of semantic progress; repeated low-value observations can still consume both attempts.

This path does not classify generic CODEX_TURN_FAILED as overflow. The experimental Codex adapter now maps only terminal turn.error.codexErrorInfo === contextWindowExceeded to CONTEXT_OVERFLOW, preserving interrupted cancellation precedence. The official protocol schema defines this typed variant and TurnError field: https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/schema/json/v2/ThreadStartResponse.json . Four mapping regressions pass, including generic errors whose message mentions context. The observed historical run did not retain this raw typed field, so coverage of that exact incident remains unproven. An explicitly supplied host deadline is checked before each provider admission, including replacement; an expired-deadline regression passes. Propagation from every real task admission path still requires verification. Admitted callback promises are awaited before replacement; one delayed-callback regression passes, but native runtime cleanup and pending steering still need adversarial integration tests. These are not solved by the journal alone.

## Initial cost measurement

One synthetic 200-attempt/410-record run measured median attempt+outcome persistence 6.80 ms, p95 13.48 ms; five full-index reads took 306–394 ms. A 20-entry metadata page was approximately 2163 estimated tokens/5763 bytes. These costs expose a retrieval bottleneck, not evidence of workflow improvement. Exact-ID inspection now reads only the requested record instead of scanning the journal; full-index and note validation still scan all events. Cache was not flushed and host load was uncontrolled. No live-model or long-running completion result exists for this design yet.

A later storage revision with durable claims and eight bounded readers measured persistence median 15.99 ms/p95 23.57 ms and index reads 83–91 ms on a separate equivalent synthetic fixture. This was not a controlled isolated comparison: both durability and reader behavior changed, cache/load were uncontrolled, and the working-view change came later. The extra write cost must be included, not hidden behind faster reads.

## Promotion gates

1. Preserve objective, obligations, inputs, completed and unknown effects through corrections, concurrent revisions, corruption and process restart. Never replay automatically.
2. Add current-action retrieval across run boundaries, exact-source inspection and a bounded working set. The reader still scans all events. Unresolved/unknown metadata now paginates with explicit totals and the same revision guard; wide conflict groups have separate revision-bound pages, so individual sibling lists are bounded too. Scale cost must be measured and improved before production.
3. Test actual models inside BLACKICE on document export/edit, browser data entry and research synthesis, plus safe job-search replay. Compare Directory off, legacy phase Directory, action Directory and isolated containment. Fix model/profile/task/order where possible.
4. Measure verified completion, elapsed time, tool/model turns, inspections and real state deltas, tokens/compactions, storage and retrieval latency, abandonment, lost obligations, duplicated effects and unresolved outcomes. Scripted runtimes test contracts, not model usability.
5. Keep the independent recovery/startup release moving. Do not restart the active app or migrate active history for this experiment.

## Working-state preview experiment

Current action heads now expose bounded objective/state/next-action previews (200 characters per field), with explicit truncatedFields and exact-source retrieval. Truncation does not remove obligations or promote agent notes to user authority. On one synthetic page of 20 action heads, previews cost 3784 estimated tokens versus 1947 without previews; reads took roughly 5-7 ms on a warm process with uncontrolled cache/load. This is a payload trade-off, not measured model efficiency. Actual Codex adapter plus Directory rollover fixture preserves a completed effect receipt before admitting the replacement session; pending steering tests retain old-session uncertainty. These remain fixture contracts, not installed native-process or live-model validation.

## Accounting and retrieval review

Provider admissions now reserve the shared maxCalls budget synchronously immediately before every runAgent invocation. Failed, cancelled and overflow-replacement sessions consume admission counts; rejected admission consumes none. Success/failure counters describe provider settlement, not verified task completion. providerSessionElapsedMs sums time awaiting provider sessions, including failures; concurrent durations overlap and are not total run wall time or monetary/token cost. No missing usage is imputed as zero. Cancellation, deadline and the two-rollover/no-new-outcome limits remain separate boundaries.

Working-page length is bounded, but read/index retrieval cost is not. Each page loads and validates every event; sorting and revision/conflict construction add work. Current phase-authority rows remain in the working projection, so phase growth also grows the result set. An 80-authority regression returns five rows while reporting 80 scanned events and 80 working entries; no authority history is discarded. The read result explicitly reports validated-full-scan and constantCost:false.

Incremental note validation now performs deduplicated exact-ID lookups: at most 100 evidence references, 100 reconciliation references, one parent and one correction. IDs are validated before path construction, and published referenced records undergo identity/content-hash checks. Missing, unpublished and corrupt records are distinct failures; unpublished reservations can no longer be cited as completed evidence. Independent notes can be added despite unrelated corruption, but this makes no global health claim: full reads still validate the entire journal. Original records and unknown effects remain unchanged. Cancellation/deadline checks occur before reference reads and queued write reservation. An already accepted write may finish after cancellation; the note remains durable, while the phase checks cancellation/deadline again before focus activation.

A synthetic ABBAAB measurement at 81/321/1281 initial events measured median note validation plus persistence of 29.21/76.52/291.07 ms before and 7.91/7.78/7.61 ms after exact reference lookup. Six legitimate distinct revisions were retained per fixture and original digests verified. Sequential warm cache was not flushed and host load was uncontrolled. This is an incremental update measurement, not bounded working-index retrieval or model effectiveness.

Promotion requires measured scale tests and an indexed projection with durable generation/rebuild semantics, cross-process publication coordination and explicit authority lineage/supersession. Selecting a global latest authority by hash ordering would be invalid, especially for concurrent phases and corrections. Until those contracts are implemented and adversarially tested, this is a structural prototype, not a sustained constant-cost solution. Original events remain the recoverable source of truth.

Parents and reconciles must reference same-action action-state events. Attempt/outcome receipts remain valid evidence and retain their original hashes, but cannot masquerade as revisions. This correction does not deduplicate actions, erase receipts or authorize replay.

Conflict semantics use the remaining revision tips for each action. Both parent and reconciles are revision edges: parent=left with reconciles=[right] retires both tips and yields one merged tip. An incomplete merge leaves the unjoined tip visible. Competing merges remain two tips even when they chose different parents; a later explicit join is required. Evidence links and corrections alone do not retire tips. Historical revisions and genuinely unknown effects remain available after a merge. This is structural resolution of agent-authored state, not independent confirmation that its claims are true.

## Explicit action association

record with focus:true durably records agent-authored state and selects that action only within the current infer phase. Await its receipt before dependent tool calls. Each attempt captures the selection at admission; its outcome inherits that immutable association, even if selection later changes. Concurrent phases have separate selections. Typed rollover retains the phase selection; process restart does not silently select an old action. The model must inspect and explicitly select working state on restart. Action-filtered retrieval includes notes, attempts and outcomes. Current heads expose host receipt counts, which are not verified objective completion. Grouped successful receipts leave the loose working index but remain in exact history; failed and genuinely unknown effects remain visible. Nothing is semantically deduplicated, retagged retroactively, cleared or replayed. This association is a model judgment, not proven causation.

A synthetic 40-attempt comparison retained all 81 journal records in each case. Explicit association reduced loose working entries from 41 to 1; all 81 remained available through the action view. First-page estimates were 2564 versus 360 tokens. This measures organization only, not model completion, and omits later exact-source reads. Unresolved/unknown metadata is explicitly conversation-wide even when actionId filters displayed events.
