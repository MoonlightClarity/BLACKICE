# Protected host-only transport boundary

> **Status: Historical documentation.** This preserved release-era design, evaluation, or migration record is **not current usage guidance or deployment evidence**. Do not infer present defaults, tool contracts, or installation state from it. See [current documentation](README.md) and [source release notes](../RELEASE-NOTES.md).

This is an opt-in execution mode. Ordinary Chat and existing provider sessions retain their configured behavior. This file describes the **source change on `fix/luna-directory-auto-20261112`**, not the installed 2.39.67 release until the change is integrated.

## Transport contract

BLACKICE's host owns tool definitions, dispatch callbacks, planning admission, and durable operation receipts. A protected provider session receives only its explicitly selected BLACKICE dynamic tools as operational tools. Unknown host tool names never dispatch through `onToolCall`. A response claiming an effect is not an effect receipt.

OpenAI Responses, compatible Chat Completions, and Anthropic Messages API adapters attach their exact host function catalogs. Existing protected API sessions store a catalog hash. They cannot resume as unprotected sessions, upgrade old unprotected history, or silently change catalogs. There is no automatic model/provider fallback.

### Native Codex (including GPT-6 Luna)

Native Codex support is **verified per connection, exact model, and working directory**. Sign-in and a connected process alone **do not** make `supportsHostOnlyToolDispatch({model,cwd})` true.

Before an initially unverified native session is admitted, `ensureHostOnlyToolDispatch` performs a **model-free preflight** against the actual app-server: discover current feature controls, disable ambient integrations and action capabilities in a fresh ephemeral thread, verify the returned read-only/network-disabled/no-escalation sandbox and effective disabled flags, then unsubscribe. No `turn/start` occurs during preflight. A failure leaves support false and prevents the protected provider turn. The proof is tied to the current Codex child process, concrete model, and directory; reconnects and other directories require a fresh check. Concurrent callers share one preflight operation but have **independent cancellation**: aborting one waiter does not abort another, and a late `thread/start` acknowledgment is still consumed and its ephemeral session unsubscribed. A transport-level RPC timeout without a returned thread ID remains an uncertainty distinct from caller cancellation; this verification does not claim recovery of an otherwise unobservable late server acknowledgment.

Each subsequent **actual protected thread also verifies those same effective settings before its first provider turn**. Preflight is a capability admission check, not a substitute for this per-thread verification. All protected native sessions use `ephemeral: true`, even when `isolatedHistory: false`; old unprotected native threads cannot be silently resumed as protected. The selected GPT-6 Luna model is preserved.

A protected native thread requests `sandbox: 'read-only'` with `networkAccess:false`, `approvalPolicy:'never'`, no environments or selected capability roots, and no inherited native apps/plugins/MCP/skills. Native shell, patch, browser/computer use, code-mode host, spawning, remote-plugin and related enabled feature families are disabled by the host configuration. Registered BLACKICE dynamic tools continue to be available through their host callback and its independent task/effect admission. The host denies attempted native permission escalations.

This is **not** a universal native global tool allowlist. The provider's feature controls, tool catalog, and sandbox are version-sensitive. The native `request_user_input` tool remains advertised on the tested version even after disabling its related feature; it was assessed as a non-operational interaction capability, **not** silently described as absent. `item/started` and `item/completed` interruption of unexpected native effect items is **a detection backstop after an item is observed, not guaranteed pre-effect prevention**. Primary prevention is excluding native effect tools from the model-facing catalog, disabling their features and integrations before a turn, and enforcing the native sandbox. The host does not claim a perfect sandbox against undisclosed future features.

### Verified installed app-server evidence — 2026-11-12

- Installed executable: `codex-cli 0.167.0-alpha.4.1`.
- Model-free probe: `verification/host-only-alpha41-adversarial.mjs`. It launches the actual Codex app-server with disposable `CODEX_HOME`, a disposable workspace, and a localhost-only synthetic Responses endpoint. It never contacts a model or remote inference provider. Set `BLACKICE_CODEX_EXE` to override the installed binary; with `ELECTRON_RUN_AS_NODE=1`, invoke it with the BLACKICE Electron executable.
- Receipt: `verification/host-only-alpha41-receipt.json`. The actual model-facing requests advertised exactly **`request_user_input` and `relay_probe`** for the tested host-protected tool profile. No shell, patch, browser, or MCP effect tool was exposed. The native host callback for `relay_probe` was invoked once.
- The synthetic endpoint supplied function calls attempting `exec_command`, `browser_use`, and `mcp__blackice_ambient_canary__touch`, plus a **native Responses `custom_tool_call`** for `apply_patch` with literal patch input. Each of all **five scenarios produced two model-facing request captures**. The authorized host case showed a real `relay_probe` callback and its `ONLY_BLACKICE_HOST` receipt in the subsequent `function_call_output` sent to the model endpoint. The four ambient attempts did **not** dispatch through the native runtime; no corresponding ambient item events or dynamic callbacks appeared, and no disposable filesystem/MCP markers were created. The browser canary was a real locally reachable HTTP route at `127.0.0.1`, and it received **zero navigation requests**. No execution marker from the configured synthetic ambient MCP server was observed; process-spawn tracing was not part of this probe.
- All five probe cases observed the native protected capability profile: read-only sandbox, network disabled, one attached BLACKICE tool, and 30 feature flags disabled.
- The measured capability probe was initially false, became true **only after** a real model-free effective-state preflight, and was invalidated when changing connection, model, or working directory (synthetic regression test).

This is empirical tool-catalog and attempted-dispatch evidence for **alpha.4.1**, in addition to feature-status assertions. It does not prove the absence of every possible undocumented native effect or guarantee an arbitrary later Codex build has the same catalog. If the installed protocol changes, rerun the model-free tool-catalog probe and fail closed on unverified essential controls.

For historical comparison, `verification/transport-boundary-evidence.json` records the older `0.167.0-alpha.3.2` capture, which also advertised `request_user_input`. Its former conclusion that all native protected execution was unsupported is superseded for the newly tested alpha.4.1 profile, **not** deleted from history.

### Live Luna acceptance

`verification/luna-native-provider-acceptance.mjs` is an optional **real GPT-6 Luna** test. It runs the native Codex transport through `ProviderRuntime` and the complete Directory sequence (decompose → work → integration), with `isolatedHistory:false` to verify fresh protected ephemeral sessions. This test **does consume native model quota** but makes no browser or file modifications outside a disposable working directory. Its sanitized receipt is `verification/luna-native-provider-acceptance.json`: actual model `gpt-6-luna`, three verified native protected phases, arithmetic output `4`, and two current working-directory capability proof scopes. No model was substituted; no ordinary-Chat fallback occurred.

### Tests and limitations

`tests/native-host-only-preflight.test.mjs` checks that authentication is not admission, a verified effective preflight issues no model turn, failures do not start inference, proof is scoped to model/directory/connection, `isolatedHistory:false` still produces ephemeral read-only protected sessions, delayed `thread/start` acknowledgment after caller abort is unsubscribed, and two concurrent waiters do not inherit one another's cancellation. Existing tests in `tests/host-only-transport.test.mjs`, `tests/planning-response-profile.test.mjs`, `tests/directory-modes-engine.test.mjs`, `tests/native-task-context-bridge.test.mjs`, and `tests/planning-browser-runtime.test.mjs` cover the remaining provider, Directory, task context and Planning paths.

**Evidence boundaries:** The synthetic tool attempt shows rejection on the tested Responses protocol, not arbitrary real-model behavior. Read-only and network-disabled are native sandbox acknowledgments, not direct OS syscall tracing. A harmless residual `request_user_input` remains; it is reported rather than concealed. Host-dispatched BLACKICE tools can still perform their authorized effects under their own independent plan and operation checks. No installer or release has been modified by this verification change.
