# BLACKICE 2.33.13: planning, Fast mode and background email

This candidate brings together fixes found while using BLACKICE for document-grounded research and external actions. Publication and verification of the exact Windows installer are separate from source and installed-runtime testing.

## Changes

- **Fast mode:** Standard/Fast is a separate saved choice from reasoning effort and Planning. Fast is offered for native models that advertise support, including the native `priority` service tier. Unsupported selections receive a specific error instead of silently changing models or speed.
- **Multi-select:** The chat selection button now says **Multi-select**, aligns with the view selector, and retains the existing visible-chat selection and reversible bulk actions.
- **Compatible APIs:** Malformed historical tool arguments no longer poison later compatible-API requests. The outgoing history preserves a bounded diagnostic in place of the invalid tool exchange; original saved history remains intact. Malformed new tool arguments report a failure without executing a guessed action. This fixes a reproduced upstream HTTP 400 trigger, while a separate intermittent transport failure remains without an established root cause.
- **Grounded planning:** Guidance uses the whole primary document to infer professional identity, level and transferable capabilities. Overall identity remains distinct from tailoring for one vacancy or recent project. Requirements, preferences, quality targets, qualification gaps and confirmed eligibility barriers are distinguished so useful partial findings survive an unmet verification target. Planning records concrete methods, checks and decisions before affected actions.
- **Continuity and coordination:** Continuing or retrying an existing task retains saved steps, evidence, decisions and recovery context through later turns and native restarts. A superseded next action stays explicitly historical and requires reconciliation before reuse. Shared Planning now settles an inactive, non-runnable coordination wait as a failure after 60 seconds, with bounded blocker diagnostics, allowing later queued work to proceed. Active but stuck model or tool calls are outside that guard; separately started chats still own separate task plans.
- **Contained background email:** A composer and agent tools support sender, recipients, body and original attachments through the configured email engine without driving a mail application's window. Prepared messages bind immutable MIME and attachment hashes, stable Message-IDs and durable delivery history. Sending reuses an identical request's receipt; queued, accepted and uncertain outcomes remain distinct, and uncertainty does not trigger automatic resending. Email receipts can reference a Message-ID, displayed as noninteractive text; these remain agent-reported evidence rather than proof of recipient acknowledgement.
- **Clearer recovery feedback:** Email readiness reflects the selected connection and actual observations. Search syntax errors remain scoped to the failed query, reads identify their required folder, and delivery history supports explicit pagination. New managed email sign-ins request sending access; existing grants retain their actual capabilities. Browser capacity feedback identifies remaining task capacity and supported recovery actions. Desktop mutations that observe foreground changes report lost background assurance while preserving possible effects; this feedback does not prevent the first activation by an external application.

## Verification and scope

Focused regressions and live dogfooding exercised native Fast mode, aligned controls, compatible-API recovery, saved-plan continuation and background email with an exact original attachment. An independent Sent-folder read matched the actual message and attachment. A separate document-only positioning probe satisfied its narrow identity and seniority criterion; it does not establish a general planning-quality grade or model success rate.

The final source suite, installer checksum, clean Windows installation checks and publication status belong to the matching release receipts. Existing native tool catalog versions remain pinned for saved conversations. Routine authorized actions gain no new per-action approval gate. This is a Windows release candidate; macOS and Linux releases are outside this update.
