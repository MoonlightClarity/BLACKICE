# General browser use

Use this skill for website work. For finding or applying to jobs, also read the separate blackice-job-search skill. Skills describe methods, not permission to act, and do not override the user's task, current tool schemas or platform requirements.

## Choose the right starting point
Start from the user's URL, known service, existing relevant task tab, or official destination when available. Use a site's own search, filters and navigation for that site's records rather than repeatedly searching the whole web. General search is useful for discovering an unknown site, finding a hard-to-locate page, comparing sources or recovering a broken route; it is not the default replacement for the service itself. A snippet is a lead, not proof of current content or availability.

## Use the actual browser
Use BLACKICE's contained relay_browser and its advertised actions. Read the current tool schema; do not invent selectors, APIs or a different browser. Inspect task-owned tabs before opening another, reuse relevant signed-in state, and keep unrelated/user-owned tabs intact. A task's empty tab list does not prove the shared profile is signed out. Open the intended site and inspect the result.

## Navigate with purpose
Read a focused snapshot or page section, identify the next useful action, then act on fresh observed controls. Use screenshots when layout or visual state matters, not as a substitute for every text read. Apply relevant filters, check pagination and sorting, and capture useful stable links. Avoid taking the same snapshot repeatedly without a hypothesis or expected change. After an asynchronous action, observe the expected URL, text or control; if stalled, diagnose that specific step, try an available alternative or move to other useful work.

## Forms and effects
Use current page labels and the user's supplied or established facts. Preserve entered fields, uploads and in-progress drafts. Reuse a verified profile rather than repeatedly asking for routine details; distinguish a reasonable operational assumption from inventing personal qualifications or credentials. Complete authorized prerequisites with available tools. A sign-in wall is a routing issue to investigate, not automatic proof that the whole task is impossible. Use observed supported alternatives and honor actual confirmation requirements.

## Recovery and completion
After a document-changed rejection, refresh the current state and reacquire controls. A click may have succeeded before the tool returned; inspect the destination and other owned tabs before repeating it. For uncertain submissions, purchases or messages, reconcile the prior effect before retrying. Do not conflate attempted, accepted, confirmed and completed. Retain concise evidence and the next unresolved step. Close only disposable task-owned tabs after preserving needed links/results; never use global cleanup on unrelated work. Report the actual outcome, not merely a successful tool call.
