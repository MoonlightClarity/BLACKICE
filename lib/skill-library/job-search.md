# Job Search

Use this method for a request to find, shortlist, or apply to open roles. Follow the actual request: a search is not permission to apply, contact a recruiter, or send documents. Apply only when the user asked for it and the route is authorized.

## Start with the posting date

- Start every board and employer search with the rolling last seven days unless the current request specifies a different window. Use the current search timestamp for the cutoff. Select each source's recent-posting filter if available, and still check the date on each lead; a source without a date filter can surface leads worth verifying.
- Prefer the original posting or opening date on the employer's listing or ATS. A public JobPosting datePosted field on the exact listing can supply it if the meaning is clear; a last-published or last-updated field cannot. If needed, check a clearly timestamped source for the same employer and requisition, and say which source supplied the date. Interpret relative dates such as "3 days ago" at the current search timestamp; if the stated precision cannot establish which side of the boundary it falls on, mark the age unverified. "Updated", refreshed search rank, a board repost date, or an "active" badge alone do not establish freshness. Count a distinctly reopened or new requisition within the window only when the employer or ATS corroborates the opening event and date.
- Check age and whether the role is still accepting applications separately. A recent posting can be closed, and an older one can still be open. Keep older or unknown-age roles out of the verified recent count; if useful and allowed, label them separately. Do not quietly widen an explicit date window to fill the requested count.
## Open more than one discovery route

- Read the current request and use the user's explicit requirements, preferences, exclusions, and limits. If no resume is needed to check the next posting, start checking it. Use work history to identify transferable skills, not to redefine the kind of work the user wants next.
- Search multiple relevant job boards and company career sites in parallel where practical. Start more than one route before spending significant time on one board. Company pages and employer ATS pages, niche boards, broad boards, and a search engine can all produce leads. Boards differ in freshness and coverage. Employer career sites are usually stronger evidence but harder to discover; use the board for discovery and the employer for verification. A search result or board badge is not evidence a role is open. If one source is unavailable or unproductive, keep the other routes moving.
- For remote startup searches, a recent publicly announced funding round or a venture firm's public portfolio jobs page can surface employers that ordinary boards miss. Use it as a discovery lead only. Open the exact employer careers or ATS listing to check posting date, remote eligibility, pay when available, and current status; a funding announcement proves none of these.
- Search for what the work produces, not only a title. If the user prioritizes intelligence research, look for postings that collect evidence, assess it, and produce briefs, assessments, or other decision inputs. Also look for adjacent work that produces substantive analysis when the request permits it, such as market insights or research operations with analysis ownership. Run direct and adjacent searches in parallel from the first pass and review them together. Adjacent work is part of the search when the user needs it, not merely an emergency fallback. Rank verified primary matches first; do not require exhausting every primary search before evaluating or using an allowed adjacent match, and do not call an adjacent match primary just because it was easier to find.
- Treat an exclusion as an exclusion, not just a lower rank. If the user wants out of gig work, check whether workers receive discrete platform tasks or whether the posting is a sustained role with a defined schedule and responsibilities. Do not assume all contracts are gig work. If the user wants to move out of producing training data, reject roles mainly grading or labeling model outputs, but do not exclude all work that happens to use AI. Check recurring duties and deliverables in the posting.

## Validate the exact role before counting it

1. Open the employer's listing or its applicant tracking system (ATS). Match the employer and exact requisition/posting ID. If a board supplied the lead, follow its link or find the corresponding employer listing; the same title alone does not establish that it is the same opening.
2. Check that the authoritative posting still accepts applications and that its application route is active for that requisition. Open the route read-only to verify it reaches the same live form, or verify that the live official posting currently directs applicants to a specific email address or equivalent intake route. Loading a page, seeing an Apply label, or finding an archived mirror is not enough.
3. A closed or archived posting, an elapsed submission deadline, or a route that no longer accepts that requisition does not count. If a generic careers page or dead link hides the status, check the employer's current openings or ATS once for the exact requisition or a replacement; verify a replacement separately. If the source is inaccessible or eligibility or status remains ambiguous, say what could not be checked and keep the lead separate from verified open matches. Do not infer closure from a broken browser reference; retry a fresh snapshot when it clearly did not dispatch, then verify status from the source. Move on to another actual opening rather than cycling through copies of the same stale one.
4. Check material criteria against the source. Note the employer, title, authoritative URL, requisition when available, dated evidence, live application route, and evidence for fit or a decisive mismatch. Mark unavailable terms honestly; do not invent pay, location, eligibility, or a qualification the user has not claimed. Rank by fit and explicit priorities rather than by search discovery order.

5. Candidates almost never meet every listed requirement. Matching every bullet is the exception, never the screen. In a narrow search, someone might meet every listed requirement in roughly one out of 500 postings while being able to do far more of the jobs. Treat that as a reminder of the gap between listing match and ability, not a measured rate or a selection rule. Assess ability to deliver the actual work separately from matching the list. Assume job descriptions are almost always inaccurate in some material respect, especially what the person will do and how much experience it takes. Treat the description as evidence, not ground truth: compare recurring duties, expected outputs, team, and any specific screening question. If those disagree with a title, generic years-of-experience line, or copied template, name the conflict and keep a credible option in consideration. Do not assume an actual mandatory gate will be waived; verify it if it changes the next step. Separate the user's actual hard filters and genuine role gates from the employer's preferred qualifications or wish list. A gap in years, title, or a named tool is not by itself a rejection. Check the few gates that would change whether the person can actually proceed, then look for evidence that the person can do the core work. Keep a candidate with credible transfer and no concrete blocker in consideration even if they miss several listed requirements. Do not require a perfect match, invent experience, or turn every listed bullet into a required plan step.

## Deliver what was asked

- **Find or shortlist:** deliver distinct verified open postings up to the requested number with the evidence needed to act. If there are fewer, report the verified count and what remains unchecked or unavailable. Opening or inspecting a form is not submitting it.
- **Apply:** after checking fit, the live route, relevant applicant evidence, and the exact duplicate state in sources authorized for this task, take the next authorized application step. Compare ATS employer plus requisition, not URL spelling or title alone. Use What Makes Done to separate verified, reported, unknown, and not-dispatched effects. Never repeat an effect that may already have happened without checking, and count only a confirmed submission as submitted. If one role cannot proceed, work another eligible opening when the user's scope permits. Stop on an actual cutoff, requested quantity, or lack of useful authorized work, and report what was and was not confirmed.

## Examples

- **Intel first; real adjacent work too.** Open a specialized intelligence board, a broader board search for research roles, and employer career sites. One live role produces threat assessments, another produces competitive research briefs, and a third is titled AI Research but spends most shifts labeling model output. For a user moving from training data to intelligence, rank the first primary, include the second as adjacent substantive analysis if permitted, and set aside the third for its day-to-day work.
- **A recent board result can be stale.** A board shows Apply for a Market Analyst role. The employer ATS for that requisition says applications closed yesterday. Do not count it or use a live-looking copy. Another opening with the same title and a different requisition can qualify if its own authoritative page shows it is open and its form still accepts applications.
- **Several gaps, still a credible application.** An intelligence analyst listing asks for five years in that title, a named platform, and a preferred sector. The candidate has three years in research operations using different tools in another sector, but has independently evaluated mixed sources and written assessments that informed decisions. Keep the role in consideration if its actual gates are met. Use those real assessments to show fit; do not claim five years, the title, the platform, or the sector experience.
