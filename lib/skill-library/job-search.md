# Job Search

Use this method for a request to find, shortlist, or apply to open roles. Follow the actual request: a search is not permission to apply, contact a recruiter, or send documents. Apply only when the user asked for it and the route is authorized.

## Start with the posting date

- Start every board and employer search with the rolling last seven days unless the current request specifies a different window. Use the current search timestamp for the cutoff. Select each source's recent-posting filter if available, and still check the date on each lead; a source without a date filter can surface leads worth verifying.
- Prefer the original posting or opening date on the employer's listing or ATS. A public JobPosting datePosted field on the exact listing can supply it if the meaning is clear; a last-published or last-updated field cannot. If needed, check a clearly timestamped source for the same employer and requisition, and say which source supplied the date. Interpret relative dates such as "3 days ago" at the current search timestamp; if the stated precision cannot establish which side of the boundary it falls on, mark the age unverified. "Updated", refreshed search rank, a board repost date, or an "active" badge alone do not establish freshness. Count a distinctly reopened or new requisition within the window only when the employer or ATS corroborates the opening event and date.
- Check age and whether the role is still accepting applications separately. A recent posting can be closed, and an older one can still be open. Keep older or unknown-age roles out of the verified recent count; if useful and allowed, label them separately. Do not quietly widen an explicit date window to fill the requested count.
## Open more than one discovery route

- Read the current request and use the user's explicit requirements, preferences, exclusions, and limits. If no resume is needed to check the next posting, start checking it. Use work history to identify transferable skills, not to redefine the kind of work the user wants next.
- Search multiple relevant job boards and company career sites in parallel where practical. Boards surface leads; employer pages verify them. If a board is unproductive, open a different named board with a recent filter or an employer career site. Rephrasing a query on the same source is not changing routes.
- For remote startups, a venture firm's public portfolio jobs page or funding announcement can surface employers ordinary boards miss. Open the exact employer listing to verify date, remote eligibility, pay and status; a funding announcement proves none of these.
- Search for what the work produces: for intelligence, search for evidence assessment and decision briefs. Run direct and adjacent searches in parallel from the first pass. Rank verified primary matches first, but do not require exhausting every primary search before checking or using a relevant adjacent match.
- Treat exclusions as exclusions. Look at recurring duties: discrete platform tasks are gig work; a sustained role with contract terms can be different. Do not assume all contracts are gig work. If the user excludes producing training data, reject roles mainly labeling or grading model outputs, not all work that uses AI.

## Search tactics with worked examples

Pick the shortest tactic that can produce a new, verifiable opening. After each batch, note which source you actually opened and why the leads failed. Change the part that failed: query terms for wrong work, source for stale copies, employer list for poor coverage, or exact posting evidence for missing dates. Do not wait for a full batch before checking the best lead.

### Everyday tactics

- **Search by the work and by neighboring titles.** Run a primary query such as `"threat intelligence analyst" remote` and a separate adjacent query such as `"market intelligence" "competitive assessments" remote`. On a broad board and a sector or remote board, use the recent filter where available. Open the most promising employer listing from each route. If a Trust & Safety role produces investigations and written assessments, it may be adjacent; if it is primarily queue moderation, change the phrase or board rather than treating the title as a match.
- **Turn a board hit into the exact employer listing.** If a board says "posted yesterday" but the button redirects to a careers homepage, search the company name plus the quoted title and requisition ID. Open the employer's exact listing and intake route. If the exact posting is closed, retire that ID; a similar title with a different ID is a separate lead. If an employer page never loads, check its public board or exact-title search once rather than interpreting a blank page as no openings.
- **Make one source change before declaring a shortfall.** If a broad board keeps showing reposts, move to a named specialist board such as Built In for tech, or the career pages of several relevant employers. Check the live form and posting date as soon as either route yields a candidate. Report "no verified matches from these sources," not "there are no jobs."

### Advanced tactics

- **Search applicant tracking system domains directly.** Try `site:job-boards.greenhouse.io "competitive intelligence" remote` or `site:jobs.ashbyhq.com "market insights" remote`. Search a different title or deliverable on `jobs.lever.co`. Use `after:YYYY-MM-DD` with the current cutoff only to discover recently updated results; it does not establish when the employer first posted. Preserve the actual employer posting link and ID, not the search result. An empty indexed search is not an inventory of open jobs.
- **Read the employer's documented public postings feed.** If an employer careers page is a blank app shell or incomplete, get the board identifier from its actual careers link and check the provider's documented public read endpoint when available. Greenhouse's exact-post response may expose `first_published`, distinct from `updated_at`. Ashby's `publishedAt` is the last publication, not proof of first publication. If a board says two days and Ashby's last publication agrees but an independently dated copy shows the same ID twelve days ago, don't count it as first posted this week. If only the last-published timestamp is available, look for the exact employer page's `JobPosting.datePosted`; if still unverified, keep it provisional. Use the actual application page to check intake, not a job-feed entry alone. Do not access private APIs or submit through a public read endpoint.
- **Start from employers instead of vacancies.** When the usual boards saturate, choose a small set of employers that would plausibly buy the target work. For example, use YC Startup Jobs, a venture portfolio page, or an original investor funding announcement to find risk or fraud startups, then open each employer's careers page and look for investigations, research, or market-insights work. If one employer is a strong fit but has nothing open, check a few direct competitors or alternative vendors that hire for the same work. Check posting age, remote geography, pay, and intake at the exact employer posting. The funding date is a reason to look, not the posting date or proof the company is hiring.
- **Recheck a watchlist without mistaking discovery for publication.** For a repeat search, use a watchlist the user supplied or asked you to maintain. Check the employer's board, a public feed, or job alerts the user authorized you to read. If an alert arrived today, record today as first seen, not first posted. If the same exact requisition reappears with a fresh tracking URL, update that lead rather than adding a second opportunity or application. No alert signup or ongoing monitoring is needed for a one-off search.
- **Resolve conflicting terms before investing in the form.** For a remote role advertising a broad national range, look at the employer's state eligibility, mandatory travel and site visits, and any location-specific base-pay tier. The exact page's `applicantLocationRequirements` and `baseSalary` can supply clues; cross-check against the listing and form. A board's remote badge, employer-wide salary range, or compensation including equity does not prove the role meets a fully remote base-salary floor. Verify what changes the next action and move on if the match is ruled out.

## Validate the exact role before counting it

1. Open the employer's listing or its applicant tracking system (ATS). Match the employer and exact requisition/posting ID. If a board supplied the lead, follow its link or find the corresponding employer listing; the same title alone does not establish that it is the same opening.
2. Check that the authoritative posting still accepts applications and that its application route is active for that requisition. Open the route read-only to verify it reaches the same live form, or verify that the live official posting currently directs applicants to a specific email address or equivalent intake route. Loading a page, seeing an Apply label, or finding an archived mirror is not enough.
3. A closed or archived posting, an elapsed submission deadline, or a route that no longer accepts that requisition does not count. If a generic careers page or dead link hides the status, check the employer's current openings or ATS once for the exact requisition or a replacement; verify a replacement separately. If the source is inaccessible or eligibility or status remains ambiguous, say what could not be checked and keep the lead separate from verified open matches. Do not infer closure from a broken browser reference; retry a fresh snapshot when it clearly did not dispatch, then verify status from the source. Move on to another actual opening rather than cycling through copies of the same stale one.
4. Check material criteria against the source. Note the employer, title, authoritative URL, requisition when available, dated evidence and its source, live application route, when you verified it, and evidence for fit or a decisive mismatch. Mark unavailable terms honestly; do not invent pay, location, eligibility, or a qualification the user has not claimed. Rank by fit and explicit priorities rather than by search discovery order.

5. **Ignore every numerical years-of-experience requirement when evaluating fit.** Do not use it to filter, rank, downlevel, or decide not to apply, even if the listing says "required" or a director role lists 10+ years. Look instead at the work the person would own: the decisions, deliverables, team or budget responsibilities, and evidence the candidate can handle them. Candidates almost never meet every listed requirement; a title or named tool is not proof of ability or inability. Look for actual comparable work under administrative, research, contract, or independent titles and give it full credit. Do not default the candidate to entry level because of a title or a years line. Use their actual results and, when they give you their own interview outcomes, use those to decide which levels to prioritize. Honor the user's actual hard filters and genuine role gates, especially a required active license or clearance. Never claim a license or clearance the candidate does not hold. A direct application field asking for actual tenure is separate from the listing's years line: fill it accurately and let the employer decide; do not self-reject.

## Take the shortest route through the application

A job application is not a deposition. Answer what the employer actually asks, in the shortest useful form. Use facts already supplied and reasonable inferences they support; do not ask for documents to prove every routine answer, volunteer gaps, add apologies, or explain why a title did not match. Keep the candidate's strongest real evidence in view.

- **Relatives at the employer:** If the candidate already answered or supplied facts that settle the question, select the answer and move on. Do not investigate employees or treat silence in a resume as proof. If optional, leave an unresolved answer blank or use a truthful "not known" option. If a required field offers neither, finish the rest and flag that one field only if it prevents submission; work the next eligible role in the meantime.
- **Sponsorship:** Use the candidate's stated sponsorship needs or other already available facts that actually answer the question. Distinguish "authorized to work now" from "need sponsorship now or in the future." Do not treat a routine field as a request for documents or infer either answer from a name or address. If the answer is settled, select it and continue.
- **Privacy:** A standard notice explaining how the employer handles application data is not, by itself, a reason to stop. Read the checkbox label, acknowledge the notice if that is all it asks, and continue when within the user's authorization. Leave optional marketing and unrelated sharing unchecked. Do not mistake a separate waiver, background check authorization, or other new commitment for a notice.
- **Experience fields:** For a general or equivalent-experience question, add nonoverlapping periods in adjacent roles that actually involved the work. Do not turn three years of supported work into zero because of a title. For a field about an exact tool, credential, or title, answer that question accurately. In prose, describe where you did comparable work, what you personally did, and what it achieved.
- **Behavioral questions in the application are the effort exception.** Answer a short prompt from a real, relevant example if the work is quick. If the employer requires lengthy new behavioral essays, a take-home, or extensive tailoring before any human contact, compare the time needed with the opportunity and other live options. Defer a high-effort form in favor of a good simpler one when warranted. That is a decision about time, not a verdict on fit. Save deeper interview preparation for a screen or interview.

**Example: Director role with 10+ years listed.** A candidate with administrative titles has evaluated conflicting sources, written decision briefs, and led research priorities. Compare those outputs and the scope they owned with the director's actual responsibilities. If they can credibly do the job and the user asked to apply, take the short application route rather than rejecting on years or title. In free text, lead with the analysis and decisions it supported; do not claim a formal director or intelligence analyst title. If the same form requires several substantial behavioral essays, weigh the time separately.

**Example: Known answers, ordinary notice.** The candidate has already stated they need no sponsorship now or later and have no relatives at the employer. Select those answers and acknowledge the standard applicant-data notice if required; do not reopen the questions or stop to request proof. A required active clearance the candidate does not hold is different: do not claim it, and move to another eligible role.


## Deliver what was asked

- **Find or shortlist:** deliver distinct verified open postings up to the requested number with the evidence needed to act. If there are fewer, report the verified count and what remains unchecked or unavailable. Opening or inspecting a form is not submitting it. "Up to N" is a cap, not a completion minimum. Find and verify each promising exact vacancy as you go instead of waiting to fill an unverified queue. If useful alternatives run out, report the honest shortfall rather than inflating the count or leaving the search open for an invented quota.
- **Apply:** after checking fit, the live route, relevant applicant evidence, and the exact duplicate state in sources authorized for this task, take the next authorized application step. Compare ATS employer plus requisition, not URL spelling or title alone. Use What Makes Done to separate verified, reported, unknown, and not-dispatched effects. Never repeat an effect that may already have happened without checking, and count only a confirmed submission as submitted. If one role cannot proceed, work another eligible opening when the user's scope permits. Stop on an actual cutoff, requested quantity, or lack of useful authorized work, and report what was and was not confirmed.

## Examples

- **Training is already provided.** The employer trains new hires on its dashboard. Asked how you turn data into decisions, describe a real dashboard or reporting workflow you built and what it helped the team decide. Do not add an unsolicited warning that the new dashboard may take time to learn. If asked directly whether you have used that exact product, answer that question accurately and, when there is room, give the relevant transferable example.

- **Intel first; real adjacent work too.** Open a specialized intelligence board, a broader board search for research roles, and employer career sites. One live role produces threat assessments, another produces competitive research briefs, and a third is titled AI Research but spends most shifts labeling model output. For a user moving from training data to intelligence, rank the first primary, include the second as adjacent substantive analysis if permitted, and set aside the third for its day-to-day work.
