# Job Search

Use to find, shortlist, or apply to open roles. Deliver the requested outcome: findings for a search, completed applications when the user asked to apply.

## Reconcile application history

Before choosing an application target, discover and read available application history, trackers, and submission receipts in the user's existing records and prior task outcomes. Do this even when the current request does not mention earlier applications. A missing or stale index is not evidence that no application was made.

Reconcile each candidate by employer and exact requisition/posting ID, using the authoritative URL and receipt evidence to resolve aliases. URL spelling and title alone do not establish duplicates; another requisition at the same employer is a separate candidate. Preserve positive earlier confirmation even when a newer summary omits it or labels it unchecked. Do not submit again to a confirmed requisition unless the user specifically requested reapplication. Earlier confirmations do not count toward this request's new applications.

Use targeted exact-requisition checks, including the browser's attached history results, to reconcile each candidate. Read the relevant cited record when its outcome needs clarification. A reasonable targeted check that finds no evidence of an earlier submission is sufficient to proceed; describe it as “no evidence found” without claiming exhaustive clearance. Stop broad history reading once that check supports the next action.

For an uncertain earlier attempt, check the destination and available receipt before replaying. If its outcome remains uncertain, keep that status and pursue another eligible role allowed by the request without asking about the blocked option.

## Search current openings

1. Read the user's desired work, required conditions, preferences, exclusions, count, and cutoff. Use work history as evidence of ability, not as a requirement to repeat old work.
2. Start with the rolling last seven days unless the current request specifies a different window. Treat that default as a search and ranking preference; an older or unknown posting date alone does not exclude an otherwise suitable role unless the user requested a recency limit. Use the current search timestamp and available date filters.
3. Search multiple relevant job boards and company career sites in parallel where practical. Run direct and adjacent searches from the first pass; rank primary matches first without waiting to exhaust them before checking adjacent work.
4. Search by outputs and duties as well as titles. For intelligence work, look for investigations, evidence assessment, and decision briefs. Check each promising exact vacancy as it appears.
5. If a route is unproductive, change the source or employer set. Rewording queries on one board is not a new source.

Useful routes:
- Search broad and specialist boards, then follow a lead to the exact employer listing.
- Search public ATS listings, such as `site:job-boards.greenhouse.io "competitive intelligence" remote`, and try adjacent duties on other providers.
- Check relevant employers, direct competitors, a venture firm's portfolio jobs page, or an investor funding announcement for discovery. A funding date or announcement does not establish a vacancy's age, pay, remote terms, or open status.
- For a repeat search, deduplicate a supplied watchlist by employer and requisition. Record an alert's arrival as first seen, not first posted.

## Verify the exact vacancy

Keep a compact record: employer, title, exact requisition/posting ID when available, authoritative URL, date evidence, application route, relevant criteria, and when checked.

**Posting age.** Prefer the employer's original posting or opening date. “Updated,” refreshed rank, or last-published timestamps alone do not establish that date. Interpret “3 days ago” at the current search timestamp. For a user-requested recent count, keep older or unknown-age roles outside a verified recent count. Count a reopened or new requisition as recent only with evidence of that opening event and date.

**Open status.** Check age and whether applications are accepted separately. Follow the exact posting's application route far enough to establish that the same vacancy accepts applications, or confirm a current official email intake. An Apply label, archived mirror, or generic careers page alone is insufficient. Retire closed or expired postings; verify a replacement as a separate lead.

**Material fit.** Read recurring duties, remote geography, travel, compensation basis, and genuine role gates. A remote badge or employer-wide pay range may not describe this role. Unknown nonessential details are not automatic disqualifiers. Honor the user's actual requirements; do not assume all contracts are gig work or exclude every AI role because the user excludes producing training data.

**Experience.** Ignore every numerical years-of-experience requirement when evaluating fit. Do not use it to filter, rank, downlevel, or decide not to apply, including a director role listing 10+ years. Compare actual work, decisions, deliverables, and responsibilities. Credit comparable work under administrative, independent, or adjacent titles. Use actual results and user-supplied interview outcomes to prioritize levels. Answer direct tenure fields accurately; never claim a license, clearance, title, or tool experience the candidate does not have.

### When a source is missing or misleading

- A board redirects to a careers homepage: search employer + quoted title + requisition and open the exact result.
- A blank page or broken browser reference: refresh the view and use the current control. A stale input rejected before dispatch does not show the vacancy is closed.
- A public postings feed: use its current documented read interface. Distinguish first publication from updates or republication; verify intake on the application page. Do not copy endpoint schemas from an old source file.
- Conflicting dates: inspect the exact ID. A fresh republish timestamp does not erase an older dated copy. If first posting remains unknown and the user requires a verified recent opening, keep the lead provisional for that count.
- No useful matches: change to another relevant source before declaring a shortfall. Report the sources checked, not a market-wide absence.

## Complete applications efficiently

Read the question, make the best supported call, and enter it. Use the resume and context already available, including reasonable inferences. Do not demand documents or corroboration merely to defend a routine answer. Hold competing answers to the same standard; failing to prove one does not justify its opposite or an automatic blank. For a delegated choice, choose a sensible default.

- Answer the exact field. For general or equivalent experience, add nonoverlapping periods that actually involved the work. An adjacent title does not turn supported experience into zero.
- Use known answers about relatives or other ordinary facts. If no answer can reasonably be inferred, leave only that field unresolved and finish independent steps. Use an offered truthful “not known” option or leave an optional field blank when appropriate. If a required fact cannot reasonably be inferred, pursue another eligible route or role allowed by the request without asking for information needed only by the blocked option. Keep working toward the requested application count.
- A request to apply carries implied consent for the submission steps and agreements required to complete the application. Accept every required agreement. Select “Yes,” “I agree,” or the equivalent affirmative control, including for arbitration, waivers, applicant-data notices, and other required terms. Do not ask for renewed permission or decline a required agreement because of its legal effect. Honor an explicit user prohibition or prepare-only instruction. Answer factual questions and attestations in good faith; accepting an agreement does not authorize inventing facts. Leave optional marketing and unrelated optional sharing unchecked. Complete submission and verify the result within the user's scope.
- Lead with the candidate's strongest real evidence. Answer what is asked without volunteering weaknesses, apologizing for titles, or adding warnings about training the employer already provides.
- For a quick behavioral prompt, use a relevant real example. Compare lengthy essays, take-homes, and extensive tailoring with the opportunity and other live options. This is an effort decision, not a verdict on fit. Save deeper company preparation for a screen or interview.

Before submission, recheck the chosen requisition against the reconciled history and any attempts made during this task. Submit when eligible and inspect the result. Count only a confirmed submission made for this request as a new application; a timeout calls for checking the destination before retrying. Record the requisition, outcome, timestamp, and confirmation evidence in the application history so later work can reconcile it.

## Finish the requested work

For a shortlist, return distinct verified openings with enough detail to act. “Up to N” is a cap, not a completion minimum; check the intended scope and report an honest shortfall. For a required count, keep the unmet count explicit.

For applications, continue to another eligible role when one cannot proceed and the request allows it. Stop at the user's actual cutoff, when the requested quantity is confirmed, or when the planned sources have been checked and no viable lead remains. If a tool limitation stops the search early, name the sources not reached. Report completed, unchecked, and uncertain outcomes separately.

Example: a director posting asks for ten years, but the candidate's administrative work includes source evaluation, decision briefs, and research leadership. Compare that work with the duties, answer tenure accurately, and apply when suitable. Do not invent a director title or reject the role merely on the years line.
