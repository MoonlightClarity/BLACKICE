# Visual CAPTCHA Handling

Use when a CAPTCHA or interactive website-verification challenge is actually visible in the BLACKICE contained browser. This procedure uses the model's own vision and BLACKICE's ordinary browser UI actions only. Do not call third-party CAPTCHA solvers, external vision services, token endpoints, or bypass scripts.

1. **Observe first.** Obtain a fresh unfiltered `relay_browser` snapshot, then `screenshot` of the same owned tab. Interpret the screenshot image with your own visual capabilities. A CAPTCHA script, badge, hidden frame or vendor name alone is not evidence that a challenge needs solving.
2. **Identify the displayed task.** Read the current challenge instructions and visible controls. If the challenge is unclear, loading, cropped, visually inaccessible, or has changed, take another screenshot or use the site's displayed refresh or accessibility option. Never invent puzzle content.
3. **Interact through the browser UI.** Prefer current observed element refs for visible buttons or controls. For a supported coordinate click, use the screenshot's `tabId`, `expectedUrl`, `expectedDocumentId` and `imageScale` to translate screenshot pixels into CSS coordinates. Use `relay_browser` `click` or other advertised actions only; do not invent drag/gesture support or manipulate hCaptcha tokens, JavaScript, network requests or browser protections.
4. **Observe each result.** After one interaction, obtain a fresh screenshot or snapshot and assess whether the challenge advanced, changed, rejected the input, or cleared. Use the site's ordinary retry/refresh if useful. If the browser refuses input before dispatch, use the returned code and current page identity; do not label it an uncertain site submission.
5. **Continue and verify.** Clearing a challenge is not proof the surrounding form was submitted. Resume the original form with current refs, distinguish filled from submitted, and verify its actual confirmation. If the challenge cannot be completed with available browser actions or the site requires a person, preserve the page and report that exact observed limitation; continue unrelated authorized work when possible.

Avoid using `relay_browser_signin` merely because a CAPTCHA appears. A visual challenge is a task step, not automatically a human-only blocker or an authorization problem. Never claim a challenge is solved without an observed successful site response.
