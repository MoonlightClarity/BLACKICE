# Explain Adoption Friction

Use this method when an apparently useful tool, process or policy is not being adopted. Reconstruct the change from the participant's position. Treat observed nonuse as evidence about constraints and incentives, rather than proof that users misunderstand the benefits or resist change by nature.

## Primitives

Adoption changes a person's expected outcome, effort, uncertainty and dependencies. Benefits and costs can fall on different people or at different times. A tool can require complementary data, colleague participation, permissions or training before it becomes useful. Expressed approval is distinct from repeated use.

## Procedure

1. Define the behavior that counts as adoption: first successful task, sustained use, migration of existing work or another observable change.
2. Segment participants by task, constraints and existing alternative. Do not average together a new user and someone with years of accumulated work.
3. Trace the actual transition: discovering the option, obtaining access, setting up, importing work, completing a task and returning later.
4. At each step, identify effort, uncertainty, loss of capability and required action by others. Use observed behavior, task walkthroughs and records where available.
5. Compare the new arrangement with the user's existing workflow in the same context. Include local workarounds and benefits of familiarity.
6. Select a small intervention that tests the suspected mechanism: migration assistance, a compatible interface, a clearer status, a missing integration or changed incentives.
7. Observe whether the predicted step improves and whether the end outcome follows. A successful signup campaign does not establish useful sustained adoption.

## Worked example

A team introduces a shared research tool. Staff praise the search feature but continue using personal folders. Observation shows that importing old documents breaks folder links, and colleagues still send updates by email. Using the new tool creates duplicate maintenance.

A demonstration of search does not address that cost. Pilot an importer that preserves document references and connect the existing update flow for one project. Measure whether participants can complete their normal retrieval and update tasks without maintaining two systems. If usage still drops, inspect the next constraint rather than declaring the pilot persuasive because people liked the demonstration.

## Output and check

Return a transition map, the suspected friction, evidence for it, a targeted intervention and the behavior that would confirm or contradict the explanation. Separate participant statements from observed actions.

## Failure boundary

Do not assume all preferences are monetary or all resistance is irrational. Avoid treating one segment's adoption as proof for every segment. Verify that the proposed intervention solves a task the user actually needs to perform.
