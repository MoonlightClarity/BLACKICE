# Organize Information for Retrieval

Use this method when users cannot locate information that already exists or when a growing collection needs a useful structure. Begin with the questions users ask and the distinctions they recognize. Treat categories, labels and search aliases as routes to an item, not as a complete theory of the domain.

## Primitives

A retrieval task has an information need, a query or browsing cue, candidate items and a success condition. An item's canonical identity can remain stable while it appears through several routes. The author's terminology may differ from the user's vocabulary. Similar words can refer to different tasks.

## Procedure

1. Collect representative retrieval tasks, including exact-title searches, natural descriptions and browsing from a broad need. Use real queries or concrete task scenarios where available.
2. Identify the distinctions required to choose the correct item. Separate topic, action, audience, format and current status when they answer different questions.
3. Choose a primary organization that supports the common tasks. Add alternate routes through tags, aliases or cross-links without creating duplicate authoritative copies.
4. Write labels that predict destination content. Test ambiguous labels against nearby alternatives and replace internal implementation language unless users need it.
5. Construct a small retrieval set with expected relevant destinations and plausible distractors. Include synonymous phrases, short queries and cross-domain terms.
6. Inspect the actual results and the route required to reach the needed detail. Check ranking, missing items, excessive candidate lists and misleading matches.
7. Revise the smallest responsible metadata or structure. Keep deep content available on demand rather than placing the entire collection in every entry point.

## Worked example

A reasoning library contains methods for unit economics, cash timing and pricing response. A user asks why revenue rose while the business ran out of cash. A category named financial performance may contain all three but does not identify the needed method.

Add a retrieval phrase such as profit versus cash to the cash-timing entry and retain its stable identity. For a query about discount break-even, route to pricing response. Test both against unrelated accounting items. The objective is that the user or agent finds the right operation, not that every query returns the maximum number of entries.

## Output and check

Return the organization, canonical item identities, labels and alternate routes, plus observed retrieval cases. Check that additions improve relevant retrieval without making unrelated tasks trigger the same large set.

## Failure boundary

A tidy hierarchy does not establish findability. Avoid forcing one item into duplicate copies merely because several categories apply. Search metadata must describe actual content; adding popular keywords can make retrieval worse.
