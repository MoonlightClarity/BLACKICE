# BLACKICE 2.24.0

## A full methods library

BLACKICE now includes 589 methods and 2,932 action definitions. The original eight methods remain alongside 581 methods from the Apache-licensed Catalyst catalog, pinned to commit `1c50eea56ea4c05de8055084583145882dc8d302`. The imported catalog retains all 2,906 original steps, source references, aliases and definitions, with 16 domains, 27 clusters and 12 source playbooks. Upstream sources, checksums, license and the BLACKICE adaptation notice ship in `lib/vendor/catalyst`.

Agents search compact pages, inspect exact method revisions and adapt relevant procedures into their normal visible task plans. Substantive tasks can combine complementary methods; simple tasks can use a single concrete action. The catalog supports the work without requiring a user to choose a method or fill out a planning form first.

Both method browsers support search, domain, phase and output filters, 20 results per page, and full procedures loaded on demand. Detail views retain instructions, inputs, results, checks, prerequisites, limitations and attribution. Choosing a method prepares a draft. Paging and delayed detail responses cannot replace a newer selection or restore an unrelated project.

Saving a reusable method preserves deep action definitions when an exact-revision source outline still matches. Current task tools also support complete aligned `methodSteps` for adapted, combined or new methods. Saved blueprints exclude execution status, evidence, artifacts and selected branches. Existing native conversations keep their originally declared tool schema; new native tasks and current API turns receive task schema v5.

## Literal black ice

The workspace now uses a locally bundled panoramic black-ice image. Visible frozen depth, substantial fractured plates and reflected edges extend behind the conversation, task plan and navigation. Shading sits on individual reading surfaces, allowing the image to show through the surrounding workspace. Increased contrast, forced colors, reduced motion, narrow layouts and keyboard navigation retain dedicated treatments.

## Background workspace and capability scope

The Agent workspace and Settings expose five priorities: contained background browsing, email, task plans and notes, swarm projects, and schedules/jobs. Each entry reports its present availability or setup requirement. The existing black-ice interface and method library remain.

The ChatGPT Bridge is retired from navigation, configuration, served UI, engine and delegated tools. Its route family returns an explicit unavailable response, and saved listener settings are not loaded. Historical files are preserved. General Windows app input is removed from the generic desktop tool; only inspection and the separate finite compatible Notepad adapter remain.

Agent browser calls use only the contained Relay driver. External Neo/Chrome/Firefox gateways, known aliases, external tab IDs and automatic browser-start fallback are blocked. The manual external-browser panel describes its controls as manual and potentially foregrounding.

## Plans before answers

Current tool-capable turns with task schema v4 or later must save their own agent-authored action plan before operational work or an answer. The engine buffers answer deltas, full messages and native agent-message items until the durable plan is published. Missing plans fail with `TASK_PLAN_REQUIRED`; measured usage and continuation receipts are retained. Prior-turn plans do not release a new unplanned answer. Existing native threads retain their original schemas. Older task catalogs and models without tools remain usable without this new gate and report the planning limitation; start a new chat with a tool-capable model for the enforced outline.

The existing task workspace provides manageable action steps, working notes, checkpoints, dependencies and result evidence. Swarms and shared projects reuse that durable state without adding a second task system. Project review remains a separate agent report against explicit criteria, not proof of correctness.

## Background email

A new `relay_email` adapter uses explicitly configured Himalaya 2.2.1 with bounded hidden processes and no shell. It supports list/search/read and durable local `.eml` drafts. Interface checks do not contact a mailbox. Successful requested account operations record separate evidence; startup never probes an account. There is no send action, remote draft upload or credential-entry flow. No user email account is configured by the release update.

## Schedules and recovery

Existing five-field calendar cron, IANA timezone handling, durable job receipts, pause/retry controls and restart reconciliation remain. The UI states that schedules run while BLACKICE is open; this update installs no always-on OS service.

## Model choices without standing access badges

The model picker and connection inventory no longer repeat “Access unverified” or present an old successful request as perpetual access. Exact native, hidden and custom IDs remain selectable. Optional details show recorded completed, failed, interrupted or timed-out attempts with time, connection scope and error information. **Try model** remains an explicit action; browsing or refreshing the catalog does not initiate inference or change the saved default.

## Validation and scope

Validation for this revised scope uses Windows regression tests, owned headless UI fixtures, hidden contained-browser sign-in/restart fixtures and the installed Himalaya CLI against a disposable local Maildir. The actual results and exact source binding are recorded separately in `UI-VALIDATION.md` and the verification receipts. Browser captures are internal QA evidence.

The previous unfinished candidate's Bridge-specific acceptance checks are superseded by retirement checks. Its historical native-model and catalog receipts are preserved as prior evidence, without being relabeled as verification of this revised source. This update patches the local source and installed application resources after backups and hash checks; it does not rebuild or distribute a Windows Setup installer.
