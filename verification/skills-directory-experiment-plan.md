# Controlled cascade experiments after recovery integration

Current Directory is phase/module based. The proposed action-based design has not been implemented. Do not attribute the observed run to that proposal. The existing run is failed and settled; that alone does not establish that all other app work is idle. Reconcile admissions and existing receipts before starting a fixture. One integration owner records every admission ID and terminal result; no automatic resumption of real applications.

## Matched configurations

Fix the model and reasoning effort, applicant fixture, task text, tool inventory, browser fixture version, initial page/storage state and elapsed-time allowance. Use synthetic applicant facts and fixture-only destinations. Record exact source fingerprint, installed version and every module toggle. Reset only disposable fixture state between runs. Counterbalance configuration order and run two repetitions per task initially; expand only ambiguous contrasts.

| Configuration | Changes relative to minimal control |
| --- | --- |
| A: control | Planning and other optional modules off; Directory off; baseline browser/recovery |
| B: recovery | A plus targeted browser/recovery implementation |
| C: sparse guidance | A plus one short recovery/progress module; Directory off |
| D: Directory | A plus currently implemented Directory; Planning remains off |
| E: interaction | B+C or B+D only when individual results identify an interaction to test |

If a source change cannot be toggled safely, compare frozen installed builds with the same disposable fixture profile. Do not label a configuration isolated if it includes other executable changes. Building and verifying a comparison build is separate from publishing it. Do not restart the user's app until all work is reconciled and safely settled.

Score independently verified terminal fixture state, elapsed time, provider/model turns (separate from Directory rows), tool calls by action, exact duplicate result hashes, meaningful state deltas, context measurements and native compactions, checkpoint/session count, branch abandonment with reason, errors and successful recoveries, duplicate effects and unknown effects. Preserve raw receipts and the measurement window. Same document ID is not an unchanged-state assertion. Distinguish no new information from a legitimate verification read after an action or delayed transition.

Include a changing form with a stale ref, an invalid argument rejected before dispatch, a lost reply after a recorded effect, a persistent blocker with an independent viable branch, missing evidence versus an actual hard requirement, and a bounded multi-step task with large observational receipts. The fixture's independent event journal provides effect ground truth; model claims do not. Never use an actual employer endpoint for matched replay. Any distinct authorized real application is measured separately after reconciliation, within the user's scope and deadline.

Candidate interventions beyond browser recovery are resumable bounded phase checkpoints, selective operational receipt summaries retaining exact originals, and progress evaluation separate from observation novelty. Rotation risks losing constraints or pending effects; summaries risk hiding actionable state; progress heuristics risk blocking legitimate repeated reads. Test these failure modes before enabling any of them. Eleven compactions followed by exhaustion establishes insufficiency in this run, not that compaction caused exhaustion or preserved all useful context.

## Test amplification, not only local success

For each injected error, measure the next ten tool calls and the interval until the next independently verified milestone. Count inspections, exact repeats, token/context deltas, reconciliation calls, branch switches, elapsed time and any unsupported effect claim. Record the same measurements for an error-free matched episode and for episodes where recovery succeeds. A local error disappearing is insufficient if observation or abandonment merely moves downstream. When compaction occurs, test retrieval of a fixed set of previously established constraints, completed-effect IDs and pending branches against the fixture journal; do not assume a compacted session retained them.

Compare B against A for upstream error reduction and downstream cost. Compare C and D independently against A, then test B+C or B+D only when their failure signatures predict a useful interaction. Include repeated observations that are legitimate (delayed transition, post-action verification, unchanged page with a changed external receipt) so an inspection-reduction intervention cannot win by suppressing necessary checking. No automatic action deduplication based on semantic similarity or document identity. Report per-task outcomes and regressions; a small mean improvement cannot hide an additional duplicate effect or abandoned viable branch.

The completed Directory audit showed that traces explained the failure: invalid navigation guards and stale controls were mislabeled as unknown effects, repeated refusals displaced prepared work, and absent profile evidence was sometimes treated as a hard qualification failure. A larger skills framework would not repair those host defects.

Use six disposable fixture tasks, each with a verified outcome: repair invalid navigation arguments; refresh a replaced field; recover a known predispatch failure; inspect a lost reply after an effect; continue independent work while that effect remains unknown; distinguish a preference from a verified hard requirement. Use the same model, reasoning level, tools, initial state, token allowance and fixture versions. Run each once with existing Directory context and once with one short evidence-derived recovery note. Counterbalance the order and preserve every trace. Never use real job submissions for this comparison.

Measure independently verified completions, duplicate external effects, unsupported claims of non-dispatch, unnecessary user interventions, tool calls and elapsed time. The duplicate-effect and unsupported-absence counts must remain zero. Only retain the note if completion or intervention improves without weakening those invariants. Six pairs provide directional evidence, not a general benchmark or a basis to claim universal reliability.

The note should link the exact failure, host dispatch evidence, successful correction and final observed state. Keep ordinary task history in Directory; do not turn every trace into a skill. Promote only a repeated, transferable correction, reviewed against at least two distinct fixtures. A note is guidance, never new permission or an executable replay. This experiment can follow the incremental recovery release and must not block it.
