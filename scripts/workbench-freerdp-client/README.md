# Native Workbench child renderer

Build with `powershell.exe -NoProfile -NonInteractive -File scripts/build-workbench-freerdp-client.ps1` after preparing the separately locked FreeRDP runtime and GCC compiler. The build statically links its C++ and cJSON support. The default runtime stage is `.build/workbench-freerdp-runtime-openssl`, with its `bin` on the child PATH, `OPENSSL_CONF` set to its `etc/ssl/openssl.cnf`, and `OPENSSL_MODULES` to its `lib/ossl-modules`. These settings are process scoped. The self-test runs with only the stage and Windows on PATH, and requires the public empty-string MD4 test vector before allowing any connection.

Successful compilation and self-test atomically save `.build/workbench-freerdp-client-build.json`, binding source and executable hashes, both dependency locks, and the staged runtime manifest. `-SelfTestOnly` requires this existing receipt and rejects changed source, executable, locks or manifest before launching anything. It cannot attach a current source hash to an unrelated older executable.

`--self-test` creates a private hidden parent and child, exercises the actual frame-copy and Win32 painting callbacks against a synthetic decoded BGRA buffer, checks input ownership and authentication rejection, and verifies unchanged foreground. It never connects to a VM. It does not prove live authentication, guest pixels, throughput, or latency.

`--stream` accepts one bounded JSON object per stdin line. Every request has a nonempty string `requestId` and `action`. Fields may be at the top level or inside `params`. Replies echo `requestId` and have either `{ok:true,result}` or `{ok:false,code,error,result?}`. No callback opens an authentication or certificate dialog. Disconnects are not retried.

For an isolated integration probe, `--stream-test-parent` accepts only `prepare` with `parent:"self"`. It creates its own invisible, nonactivating parent instead of attaching to BLACKICE. A separate explicit `connect` request is still required before any network work. This mode is not the product UI path.

Actions:

- `prepare`: `parent` decimal HWND string, `x`, `y`, `width`, `height`. Creates a hidden `WS_CHILD | WS_EX_NOACTIVATE` viewport before any connection.
- `connect`: discovered `vmId`, host `127.0.0.1` or `localhost`, port `2179`, trusted `certificateSha256`, timeout `1000..30000` ms. Native Windows SSPI uses the current process logon. No account or secret arguments are accepted. Success requires certificate validation, successful connection, and an actual decoded frame.
- `bounds`: bounded child position and dimensions. Changes only the viewport; guest resolution remains unchanged and pixels scale to fit.
- `visible`: Boolean `visible` (or `enabled`); shows with `SW_SHOWNOACTIVATE`.
- `input`: `enabled:true` yields input to the user; `false` gives it to the agent and releases held guest keys/buttons. Agent events use `kind:"mouse"`, guest `x`,`y`, RDP mouse `flags`, or `kind:"key"`, `scanCode`, RDP keyboard `flags`. Events are queued only for the current owner. No host input is synthesized.
- `wake`: explicit `expectedOwner:"agent"` or `"user"` must match the current connected input owner. Queues only a guest pointer-move at its last known position (or the surface center), through the same ownership fence. It never takes/cedes control, sends keys/clicks, or activates host focus. The `wake` receipt confirms `requested:true`, `queued:true`, `desktopAwakeConfirmed:false`; subsequent decoded pixels, rather than queue acceptance, determine display health.
- `status`: connection, certificate, input ownership, native child HWND, `decodedFrames`, and same-session surface dimensions/frame sequence.
- `capture`: without a path returns a surface receipt. With a new absolute `path`, writes an exclusive BMP of that same decoded surface and returns byte length/SHA256. Existing files are never replaced.
- `sample`: `points:[{x,y},...]` with 1 to 64 integer coordinates within the guest surface. Returns width, height, frame sequence/time, and `{x,y,r,g,b}` for each point from one frame-lock snapshot. No host pixels are read.
- `close`: aborts pending connection and disconnects; bounded shutdown exits only this helper.

The viewer observes parent destruction and polls parent/child identity as a fallback, then closes its connection. Under user ownership, button-down captures the mouse for dragging; capture loss and ownership changes release held guest buttons. Input dispatch is fenced through ownership changes so an old owner's queued events cannot be sent after the new ownership receipt. Capture metadata and BMP bytes are recorded under the same surface lock.

The presentation path verifies that its parent belongs to the launching application and retains a process-lifetime handle. While shown, it leases `WS_CLIPCHILDREN` on that parent and `WS_CLIPSIBLINGS` on overlapping direct children owned by the application or its Chromium descendant processes. It raises only its own `WS_CHILD` within that parent, using `SWP_NOACTIVATE`; it never raises the application among desktop windows. Show, bounds, decoded updates, reorder notifications and a timer maintain this sibling order. Hide and normal cleanup remove only style bits this helper added, after rechecking each window/process identity. This prevents an Electron `Intermediate D3D Window` sibling from covering the decoded guest viewport.

`status.presentation` distinguishes actual child visibility, sibling order, style leases, paint/empty-clip/failure counts, last painted surface sequence, and the `StretchDIBits` scanline result. A nonblack decoded BMP alone does not prove that the native child reached the composed screen. The no-network self-test verifies the exact GDI painting function against known pixels in an owned memory DC and verifies sibling/clipping restoration; visible GPU composition requires the explicit `verification/probe-workbench-native-electron.cjs --visible-composition --output=<absolute receipt>` probe. That probe keeps GPU acceleration enabled, uses only an owned nonactivating window and compares its actual desktop-capture viewport against the independently decoded BMP through hide/show cycles. By default it sends no guest/host input or ownership changes. An additional explicit `--wake-display` flag permits one guest pointer-move wake after checking the actual Workbench agent ownership/revision; its receipt records the input attempt and queued-only result. This standalone guard is polling-based; product Wake uses the atomic server ownership queue. Do not count a hidden-window geometry test as visible-composition acceptance.

`status.frameHealth` samples RGB values only from the decoded guest buffer and reports `dark`, `not-dark`, or `unknown`, a sequence and frame age. A dark display is not evidence that the VM is off; a cached nonblack surface is not proof that a sleeping guest has awakened. `presentationReady` additionally requires a verified visible child, sibling/clipping protection and a successful GDI paint. An empty paint clip can mean another application covers BLACKICE; it must not trigger an automatic viewer close, reconnect, Wake, Take or Cede. Workbench provides explicit Start VM, Wake display and graceful Shut down VM controls. The wake backend accepts the existing user-control receipt when the user owns input and preserves that owner throughout.

The viewport never calls `SetForegroundWindow` or `SetActiveWindow`. `WM_MOUSEACTIVATE` returns `MA_NOACTIVATE` under agent ownership. Keyboard focus is requested only following an actual user mouse-down while user ownership is enabled. The UI must remain gated until live authentication, pixels, input, foreground transitions, and performance are separately verified. The helper is not bundled in the installed application yet.

The pinned FreeRDP 3.32.2 client defaults to `ExtSecurity=true`. Its `/vmconnect` option disables security negotiation but leaves that flag enabled, selecting `HYBRID_EX` (8). The Hyper-V console connection then stalls waiting for an Early User Authorization Result. This helper explicitly sets `ExtSecurity=false` while retaining NLA, selecting the console's `HYBRID` (2) protocol. A bounded live probe subsequently reached `CONNECTION_STATE_ACTIVE` with the VMMS certificate pin and native current-logon SSPI. No certificate exception, credential prompt, host policy change, or custom SSPI adapter was needed. Transport activation alone does not establish a complete guest desktop or acceptable performance.

The native self-test uses the same VMConnect protocol configuration function after the real command-line parser. It also verifies empty paint transactions do not count as decoded frames, exercises a synthetic dirty decoded frame, and checks public connection/transport diagnostic callbacks using buffer-free fixtures. Runtime diagnostics expose state names and I/O counts/times only; authentication token and credential buffers are never inspected or logged.

A sleeping guest display can initially produce a valid blank console surface while a guest-agent desktop capture remains visually stale. A bounded live check verified the same active console session and current guest time, then an explicit agent-owned pointer-move-only event woke the display and produced matching Windows 11 desktop pixels. The helper does not wake the guest through hidden keys or automatic pointer movement. Standard FreeRDP focus-in sends Tab key releases and keyboard-toggle synchronization, so it is deliberately not injected during connection or user ownership. User interaction or an explicit agent-owned input operation can wake the display.
