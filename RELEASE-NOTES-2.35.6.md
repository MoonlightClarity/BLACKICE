# BLACKICE 2.35.6 — Planning and judgment checkpoint

This checkpoint brings the completed Planning, analytical-judgment, and recurring-work changes since the last published release, 2.35.2, into one release.

## Planning and practical judgment

- **Planning is On or Off.** On requires current-turn planning with concrete procedures, intended work products, and observable completion checks. Off removes the automatic planning requirement while retaining existing plans and optional tools. Historical Auto and Maximal selections map to On; model reasoning effort remains a separate choice.
- **Ground consequential choices in the actual task.** Shared analytical guidance keeps diagnoses and remedies provisional until supported, asks for concrete comparisons where they can change the answer, and preserves established facts, accepted user decisions, and clear bounded requests. More steps or more planning prose do not establish better reasoning.
- **Match requirements to the next useful action.** Evidence and fit thresholds account for stakes, reversibility, learning value, and the cost of waiting. Requirements needed for a later commitment should not automatically block an appropriate earlier step. Genuine user constraints and truthful claims remain binding.
- **Record judgment and results without needless rework.** Optional plan fields distinguish hard gates, material barriers, adaptable gaps, preferences, and unresolved facts, with supporting sources and observations. Completion feedback identifies misplaced findings and explains how to save actual evidence without repeating completed work. Historical plans and native tool schemas remain compatible.

## Recurring work and results

- Saved Chat messages retain uploaded filenames, and the Planning and Tasks workspaces receive their required browser modules correctly.
- Non-parallel, single-agent cron and interval tasks can continue their saved conversation and Planning task across occurrences. Other workflow shapes retain their existing execution behavior.
- The Schedules workspace supports inspection and revision-checked editing. A local Results inbox keeps saved results separate from execution status and acknowledgement.
- Optional HTTP(S) webhook delivery records attempts and uncertain outcomes. Delivery is an explicit choice; queued work does not count as delivered, and results are not automatically pushed into ChatGPT.
- Schedule edits preserve active jobs and prior receipts.

## Release verification and developer tooling

- Corrected the Windows package verifier to accept the three tracked native C# helpers used by the desktop runtime while continuing to reject unrecognized helpers, untracked files, private paths, and generated backups.
- Added executable acceptance fixtures and recorded native evaluations for distinct debugging causes, exact-edit scope, atomic SQLite imports, audience-sensitive editing, and application decisions. Objective output checks remain separate from semantic review.
- Native follow-ups support the targeted completion-recovery correction. The application examples already chose appropriate actions before the latest clarification; the follow-up made the timing of a remaining check clearer. These bounded observations do not establish a universal reasoning-quality fix or a measured general performance improvement.

The release's verification receipt records the exact source, Windows installer, and completed release checks. Earlier candidate receipts do not substitute for validation of this release.
